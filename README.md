# AI写代码
## 阶段一：把 AI 变成你的“副驾驶”（嵌入式助手）
你在网页上用 AI，需要把代码复制出来，贴给 AI，再把 AI 改好的代码复制回去。而别人只是省去了“复制粘贴”的步骤。

+ **Copilot（AI 编程助手）：** 这是最基础的进阶。像 GitHub Copilot、Baidu Comate 或者通义灵码。它们作为插件直接安装在你的代码编辑器（如 VS Code）里。
    - **怎么自动改？** 你在写代码时，它会像手机输入法一样，**自动预测**你下一行想写什么，你按一下 Tab 键代码就自动补全了。你选定一段写错的代码，右键点“修复”，它就直接在原地帮你改好。

## 阶段二：把工具直接换成“AI 原生编辑器”
如果说 Copilot 只是给传统汽车加了个“定速巡航”，那么**全自动 AI 编辑器**就是“智能座舱”。

+ **Cursor / Windsurf（AI 原生 IDE）：**这是目前技术圈极其火爆的概念。它们不是插件，而是一个全新的写代码软件（虽然长得很像 VS Code）。
    - **怎么自动改？** 它拥有“理解整个项目”的能力。你不需要一行行教它，只需要在软件里按快捷键（比如 `Ctrl + K`），直接输入一句话：_“帮我把这个页面上的按钮改成蓝色，并且加上点击跳转功能”_。
    - **震撼之处：** 它会自动定位到相关的几个代码文件，**当着你的面把代码删掉、重写、改好**，你只需要点击“接受（Accept）”即可。它甚至能自己运行代码去检查有没有报错。

## 阶段三：给 AI 派发任务，让它自己去干活（AI Agent 时代）
这就到了更高级的概念——**AI Agent（智能体）**。

+ **AI Agent / 自动化工作流：**网页 AI 是“你问一句，它答一句”；而 Agent 是“你给它一个目标，它自己规划步骤去完成”。
    - **怎么自动改？** 比如 Devin 或 OpenHands 这类 AI 软件工程师。你给它提一个需求（比如：_“帮我写一个天气预报网页并上线”_），它会自己去查网上的天气 API 接口、自己创建文件、自己写代码、遇到报错自己看日志修改，直到把成品交给你。

# AI概念
## RAG（检索增强生成 - Retrieval-Augmented Generation）
+ **大白话：** 相当于**给 AI 翻书考试**。
+ **为什么重要：** 网页版的 AI 只有它训练时学到的知识。如果你公司自己写了一套独特的单片机驱动框架，通用的 AI 根本不知道。
+ **怎么用：** 比如在 Cursor 里，你可以把你们公司的“私有代码库”或最新的“芯片手册 PDF”喂给 AI（这就叫 RAG）。AI 会先去这些文档里“翻书”检索，再结合它原本的能力帮你写代码，这样生成的代码绝不会胡编乱造。

## Context Window（上下文窗口）
+ **大白话：** AI 的**运行内存（或短期记忆力）**。
+ **为什么重要：** 以前的 AI 记忆力短，你发一个几千行的 Keil 整个工程过去，它就“断片”了。现在的模型（如 Gemini、Claude 3.5）上下文窗口极大，能一次性吃下几十万字、甚至上百万字。
+ **代码场景：** 这意味着现在的 AI 能够**同时阅读你项目里的好几个 **`**.c**`** 和 **`**.h**`** 文件**，理解它们之间的调用关系，而不是只看单份文件。

## Reasoning Models（推理模型 / 思考型模型）
+ **大白话：****“先思考、后作答”** 的 AI。以 OpenAI o1/o3 系列、DeepSeek-R1 为代表。
+ **为什么重要：** 普通的 AI 是顺着嘴往下溜字（直觉反应）；而推理模型在回答你之前，会在后台自己推演、debug、算逻辑（你会看到它显示“Thinking for 15s”）。
+ **代码场景：** 极其适合用来写**复杂的嵌入式算法、高难度的逻辑状态机、或者排查隐藏极深的 Bug**。

## MCP（Model Context Protocol - 模型上下文协议）
+ **大白话：** AI 界的“USB 统一接口”。由 Anthropic 公司提出，现在已经是 2026 年技术圈的最火概念之一。
+ **为什么重要：** 以前 AI 想连你的 Keil、连你的本地电脑、或者连你的数据库，每个工具都要单独给 AI 写一套对接代码。
+ **怎么用：** 有了 MCP 协议，只要工具和 AI 都支持这个标准，AI 就能像插上 USB 鼠标一样，直接读取你的本地文件、运行你的本地编译器、甚至去查你的 Git 提交记录。它让 AI 真正连接了物理世界的文件和工具。

# 输入/输出/缓存命中
+ **输入（Input）** 是你发给模型的全部内容，包括系统提示（System Prompt）、历史对话记录和本次用户消息。这些内容拼在一起，按 Token（词元）数量计费。Token 数越多，费用越高。
+ **输出（Output）** 是模型逐字生成的回复，也按 Token 计费。Output 的单价通常比 Input 贵 3～5 倍，因为生成远比"读取"计算量大。
+ **缓存（Cache）** 解决了一个常见问题：很多应用每次请求都带同样的 System Prompt（比如一段几千字的说明书），模型每次都要重新处理这段内容，既慢又费钱。缓存的思路是：第一次处理后，把这段文本对应的中间计算结果存起来，下次直接复用。
+ **缓存命中（Cache Hit）** 是指本次请求的输入前缀与缓存里保存的内容完全匹配，模型直接读取已有结果，跳过重新计算。速度更快，价格通常是正常 Input Token 的 10%～20%，节省非常明显。
+ **缓存未命中（Cache Miss）** 是指输入前缀在缓存里找不到。模型需要从头完整计算，同时把这次的结果写入缓存（Cache Write），以便后续命中。Cache Write 的价格和正常 Input Token 相当，有的 API 略高。

# 上下文窗口
有些大模型会说自己有 1M token 上下文窗口，这意味着模型最多能看到的文字（token）数量，超过1M则会“忘记”，**<font style="color:#DF2A3F;">上下文越长，速度越慢、费用越高</font>**。



两次对话的上下文，由于大模型没有记忆，每次进行对话都会将历史对话一起发送给大模型：

> 每轮发送 = [CLAUDE.md 内容] + [对话历史] + [你的问题]
>

其中`[CLAUDE.md 内容] + [对话历史]`会以缓存命中的价格收费，价格更低，但随着新对话不断增加，历史对话也在不断增加，消耗的 token 会更多。当上下文超过 1M token，则会“忘记”最早的历史对话内容。

可以使用`/compact`命令对上下文进行压缩，压缩会消耗正常的 token 价格，压缩后会大大减少历史对话的内容。**<font style="color:#DF2A3F;">因此，除非上下文窗口消耗完毕，否则不建议压缩</font>**。

# 使用大模型的API key的正确姿势
+ 编写`claude.md`，每次启动 Claude Code 时它会自动把这个文件的内容塞入上下文开头。本质上就是一个自动化的系统提示词，解决的正是"每次开新对话什么都忘了"的问题。

```markdown
# 项目概述
项目名称：[xxx]
芯片：[STM32F103C8T6 / STM32F407VGT6 / ...填实际型号]
开发环境：Keil MDK 5.xx
库：[CMSIS + SPL 标准外设库 / HAL / 纯寄存器，三选一]
主频：[72MHz / 168MHz / ...填实际配置]

# 目录结构
[项目名]/
├── Application/     - 业务逻辑（main.c 及功能模块）
├── Drivers/         - 外设驱动（自己写的）
├── CMSIS/           - ARM 内核文件，不要动
├── StdPeriph_Driver/- 标准库，不要动
├── User/            - startup 启动文件、中断向量表
└── [项目名].uvprojx - Keil 工程文件

# 编码约定
- 寄存器操作用位运算（|= &= ~），禁止用魔数
- 禁止 malloc/free，所有缓冲区静态分配
- 中断函数命名遵循 CMSIS：TIM2_IRQHandler、USART1_IRQHandler 等
- 延时函数用 SysTick，不用空循环 delay
- 全局变量加 g_ 前缀，静态变量加 s_ 前缀
- 头文件统一加 #ifndef __XXX_H / #define __XXX_H / #endif 保护
- 每个驱动文件对应一个 .h，接口在 .h 里声明

# 外设使用情况
- USART1：调试串口，波特率 115200
- TIM2：[用途，如 PWM 输出，频率 1kHz]
- I2C1：[用途，如 OLED，地址 0x3C]
- SPI1：[用途，如 W25Q64 Flash]
（没用到的外设删掉这几行）

# Keil 工程配置
调试器：ST-Link V2
下载算法：STM32F10x_128.FLM（按实际芯片填）
优化等级：O0（调试）/ O2（发布）
C99 模式：已开启
微库 MicroLIB：[开启 / 关闭]

# 注意事项
- 修改时钟配置必须同步更新 SystemCoreClock 变量
- Keil 工程路径不能有中文
- 标准库文件不要直接修改，需要改行为请在 Application 层覆盖
```
